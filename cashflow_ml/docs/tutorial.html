Tutorial · cashflow_ml

From a bank statement to a set of accounts

A property company's bank export goes in as a CSV. What comes out is a categorised ledger, a profit and loss, a database that grows month by month, and an Excel workbook that recalculates. This walks the whole chain, in order, assuming you have written no Python before.

  • Three tools Python · SQL · Excel
  • Sample data 39 transactions, 12 months
  • Needs Python 3.10+

01The shape of it

Two independent paths out of the same CSV. Knowing which one you are on explains most of what follows.

02Before you start

Three things to install once. Everything after this is just running commands.

  1. Python. From python.org. On Windows, tick Add Python to PATH and leave tcl/tk and IDLE ticked — that second one is what draws the summary window.
  2. The libraries. One command, and it only needs doing once.
  3. The project files. Put them in a folder you can find. Keep the structure: cashflow_ml.py at the top, the sql folder inside it.
# Windows PowerShell
& C:\Python314\python.exe -m pip install pandas scikit-learn matplotlib openpyxl

# macOS / Linux
python3 -m pip install pandas scikit-learn matplotlib openpyxl
LibraryDoes whatNeeded for
pandasTables in memoryEverything
scikit-learnThe machine learning modelsThe analyser
matplotlibChartsThe charts tab
openpyxlWriting .xlsx filesThe workbook

sqlite3 is not on that list because it comes with Python. That is the whole reason the database part needs no setup at all.

Check it worked

Run the analyser with --check. It prints which file is running, which Python, and whether each library is importable. If anything says MISSING, that is your problem, and the line above tells you which install to repeat.

03The data

Seven columns. Get these right and everything downstream works; get the dates wrong and every figure is quietly wrong.

date,description,paid in,paid out,counterparty,property,document
01/04/2025,COMMERCIAL RENT COMM-04,3200,,TENANT - KESTREL TRADING LTD,COMM-04,RENT-COMM-04-202504
03/04/2025,COMMERCIAL MORTGAGE INTEREST COMM-04,,1450,MERIDIAN COMMERCIAL,COMM-04,CMTG-202504
05/04/2025,MANAGING AGENT COMM-04,,256,HORIZON COMMERCIAL,COMM-04,INV-HC-202504
ColumnRule
datedd/mm/yyyy. UK order, day first
descriptionThe bank narrative. This is what the models read
paid in / paid outOne or the other, never both. Leave the unused one blank
counterpartyWho the money came from or went to
propertyWhich property, or blank for company-wide costs
documentInvoice or reference number. The audit trail

The date trap

The code is told the format is day-first. If your file is 2025-04-01 or American 04/01/2025, it will either error or — worse — read 5 April as 4 May, moving transactions between months and changing every monthly figure without any warning. Check the first row before trusting the output.

Make your own file in Excel or Notepad, save it as CSV (comma delimited), and put it next to the script or in the data folder. Turn on file extensions in File Explorer so you can see it really is .csv and not .csv.txt.

04Run the analyser

One command. Roughly ten seconds. Four kinds of output.

& C:\Python314\python.exe "C:\Users\you\Downloads\cashflow_ml.py"

Add --no-window to skip the window, or a file path to point it at a different statement.

05Build the database

This is the step that turns a one-off analysis into a record. It is also the part most worth understanding, because it is the part employers ask about.

cd sql
python build_database.py                        # every CSV in ../data
python build_database.py march.csv april.csv    # named files
python build_database.py ~/statements           # a whole folder
python build_database.py --reset                # start over

Three tables, not one sheet

A spreadsheet repeats "MERIDIAN COMMERCIAL" on every row. A database stores it once in a counterparty table and points at it by number. Rename it in one place and every transaction follows. That is what normalised means, and it is the main thing a database gives you that a spreadsheet cannot.

TableHolds
counterpartyEach company, once
categoryEach nominal category, and which side of the P&L it sits on
transactionsEvery bank line, pointing at the two tables above

Running it twice changes nothing

Load the same file again and you get:

  bank_company.csv: 0 new, 39 already present

A unique index treats same date + description + company + amount + document as the transaction you already have, so the second attempt is ignored rather than doubling your income. The word for this property is idempotency, and it is the single most important thing about a data load in finance. Without it, someone re-runs a script on a Friday afternoon and the accounts are wrong on Monday.

New descriptions get flagged, not hidden

When something arrives that no category rule covers, it is still loaded — on the correct side of the profit and loss, decided by whether the money came in or went out — and named at the end of the run:

These descriptions matched no category rule. They are still
loaded, on the correct side of the P&L, but add a rule to
CATEGORY_RULES to code them properly:
  DILAPIDATIONS SETTLEMENT
  INSTALMENT TO HMRC

Asking it questions

python run_queries.py                     # all eight queries
python run_queries.py monthly_cashflow    # just one

The queries live in queries.sql as plain text you can edit. They cover the headline figures, monthly cash flow with a running total, the profit and loss, totals per company, recurring versus one-off payments, and three audit checks — missing document references, unusually large payments, and how concentrated the income is.

06Build the workbook

Six sheets where every figure is a formula, not a pasted number.

python build_workbook.py             # from one CSV
python build_workbook.py --from-db   # from the whole database
SheetContents
SummaryHeadline figures, each one a link to another sheet
TransactionsThe statement as a filterable table; amount, direction, category and month calculated
Monthly cash flowSUMIFS by month, with a running total
Profit and lossSUMIFS by category, income then expenditure
By companyWhat has accumulated with each counterparty
CategoriesThe keyword rules — the only cells you edit

The colours follow standard financial modelling convention, so anyone in an accounts department will read them without being told: black is a calculation, blue on yellow is an input you may change, green is a link to another sheet. Negatives sit in brackets, zeros show as a dash, and every sheet is set to print on one page wide.

Why formulas rather than values

Change a figure on the Transactions sheet and the profit and loss, the monthly cash flow and the dashboard all move with it. A workbook of pasted numbers is a photograph; this one is a model. It is also the difference between a reviewer being able to check your work and having to take it on trust.

07The monthly routine

Once it is set up, this is the whole job.

  1. Export the month's transactions from the bank and save as CSV with the seven columns.
  2. Load it: cd sql then python build_database.py april.csv.
  3. Read what it says. New rows added? Anything flagged as uncategorised?
  4. Rebuild the workbook: python build_workbook.py --from-db.
  5. Open it, check the profit and loss ties to what you expect, and file it.

Two minutes, and the database holds every month you have ever loaded. If you load the wrong file, load it again — nothing duplicates. If you want to start clean, --reset.

08What's happening inside

The same job — decide what each transaction is — done three ways.

The three models

ModelJobReplaces
KMeans
clustering		 Groups transactions whose wording is similar, without being told what to look for Eyeballing a statement for what repeats
Naive Bayes
classification		 Learns from keyword-labelled examples, then codes every line — including wording it has never seen Coding transactions to the nominal ledger by hand
IsolationForest
anomaly detection		 Scores size, timing and how often something repeats, and flags the odd ones The "what looks wrong here" pass

Both text models first convert words into numbers using TF-IDF, which scores each word by how often it appears in one transaction and how rare it is across all of them. "Commercial" appears everywhere so it carries little information; "insurance" appears once so it is highly distinctive. Models do arithmetic, not reading — this is the step that makes that possible.

About that 100% accuracy

On this file the classifier scores 100%, and that is not an achievement — it is a symptom. Six descriptions with completely separate vocabulary are trivially separable, and a simple lookup table would do just as well. The model earns its place when a new supplier appears with wording the rules never anticipated. Say this before anyone asks; it reads as judgement rather than as a gap.

The same decision in SQL and in Excel

Worth seeing side by side, because knowing where each tool stops is more useful than knowing any one of them.

ToolHow it categorisesLimit
PythonTrained classifierNeeds enough data to learn from
SQLKeyword rules in the loaderOnly matches what you listed
ExcelINDEX/MATCH/SEARCH against a rules sheetOnly matches what you listed

The rules live in one file, chart_of_accounts.py, shared by the loader and the workbook. They used to be duplicated, and the two copies drifted: the database filed a service charge receipt as income while Excel called it uncategorised — the same transaction, two answers, in one reporting pack. One list fixed it.

09Making it yours

Add a category

Open chart_of_accounts.py and add a line. The database loader and the Excel workbook both pick it up; nothing else needs touching.

CATEGORY_RULES = [
    (("rent",), "Rental income", "income"),
    (("ground rent", "freeholder"), "Ground rent", "expense"),
    ...
]

Order matters — the first keyword found in the description wins. Put the more specific rule above the more general one, or "ground rent" will be caught by "rent" and booked as income.

Add a query

Append to queries.sql with a -- @name line above it. The runner picks it up automatically.

Change how much gets flagged

In cashflow_ml.py, contamination=0.1 means "expect about 10% to be unusual". Raise it to see more, lower it to see only the extremes. It is a judgement call about how much review you want, not a setting with a correct value.

10When it breaks

SymptomCause and fix
Nothing appears at all You are running an old copy of the file. The first line printed must be cashflow_ml 1.4. If it is not, download the current version and save over it — watch for cashflow_ml (1).py
Terminal output but no window It opened behind the terminal. Check the taskbar or press Alt+Tab. If it is genuinely absent, run --check and look at the tkinter line
Could not find the bank statement CSV It lists where it looked and what it can see. Usually the filename does not match or Windows saved it as .csv.txt
ModuleNotFoundError A library is missing. Re-run the pip install from step 2
Charts tab says it needs matplotlib Exactly what it says. Everything else still works without it
Figures look wrong by a month Date format. Check your CSV is dd/mm/yyyy

The diagnostic

python cashflow_ml.py --check prints the script path, the interpreter, and whether each library imports. It answers most of the table above in one line each.

11Talking about it

What to lead with, and what to get in first.

Lead with the business reading, not the models. A statement is only interesting for what it tells you. On the sample data: rent is 100% concentrated in one tenant, interest cover is roughly 1.9× after costs, the £9,100 directors' payment is discretionary and single-handedly causes the June deficit, and there is no maintenance spend at all across a full year for a commercial property — which is either a full repairing lease or a gap worth asking about.

Then describe the mechanism in one breath. "It reads a bank statement and turns it into a set of accounts. One function cleans the data; three small models do what a bookkeeper does — group the recurring streams, code each transaction, flag the odd ones. The rest builds the outputs."

Get the caveats in before they are asked. The 100% accuracy on 39 rows. That the profit is cash basis and not a statutory figure — no accruals, no prepayments, no depreciation, no tax. Naming a limitation yourself reads as judgement; being shown it reads as a gap.

Be ready to change something live. Adding a category takes one line in chart_of_accounts.py. If you can do that while talking, the question of who wrote it stops mattering.
